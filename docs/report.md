# transformer-lab 实验报告

从零实现 Llama/Qwen 风格的 Decoder-only Transformer，在单张 RTX 5060 Laptop（8 GB）上预训练小模型、做结构消融，再让这套实现载入 Qwen3-0.6B 的官方权重，用手写的 LoRA 在 GSM8K 上做 SFT。数字都是实际跑出来的，原始记录在 [experiments/](../experiments/)；复现命令见 [README](../README.md#复现结果)。

## 摘要

- **实现正确：** 自研架构载入 Qwen3-0.6B 后，fp32 下 logits 最大误差 1.73e-04，唯一的差别是除以 √d 的浮点写法；加上 RMSNorm 内部转 fp32 的开关后，GPU bf16 下三个提示的每一层和 logits 都和官方实现逐位相同（用 KV 缓存的贪心生成也完全相同；不用缓存时，3 个提示里有 2 个在生成后段分叉）。
- **手写 LoRA 和 PEFT 逐位相同：** 从同一个起点、用同样的数据训练 454 步，每一步的 loss、学习率、梯度范数都一样。
- **结构消融（同 1 亿 token，2 个种子）：** RoPE、SwiGLU 更好，Post-LN、正弦位置编码、GQA-2、MQA 更差，RMSNorm 和 LayerNorm 差异不显著（按项目自己的判定规则，见第 3 节）。
- **LoRA SFT 学会了格式和停下，没有明显提高准确率：** GSM8K 500 题上，基座 46.8%（few-shot）/ 48.4%（不给例子），SFT 后 r=8 两个种子的均值 49.2%；高出的 0.8–2.4 个百分点不超过两个种子之间的 3.2，按同一条规则差异不显著。不给例子时在 eos 停下的题从 32/500 变成 483/500 和 484/500。

## 1. 目标和约束

- **学习项目：** 目标是能讲清每一行。注意力、Block、GPT、训练主循环、BPE、RMSNorm、SwiGLU、RoPE、GQA、`LoRALinear`、SFT 的标签构造由作者亲手写；配置开关、KV 缓存、权重转换、评测、汇总和实验脚本由 AI 编程助手写，并在手写的文件里逐处标注。
- **不用现成实现：** 模型、注意力、归一化、位置编码、训练循环、LoRA 都不用 `nn.Transformer`、`nn.MultiheadAttention` 或 `transformers`、`peft` 的模型类；`transformers` 和 `peft` 只在对照脚本和测试里出现，有测试检查这一点。
- **硬件：** RTX 5060 Laptop 8 GB（WSL2），bf16 autocast；Mac 跑单元测试、CPU 冒烟和 fp32 的权重对齐。
- **工程做法：** 先写失败的测试再实现；提交前故意把代码改错，确认测试能抓到；每个功能由两个只读子 agent 分别按规范和需求审查；实验只通过配置文件运行，结果表只追加。

## 3. 结构消融（M3）

每个变体和对照组只差一个组件，同样 1 亿 token（3052 步），2 个种子，在完整验证集（5,414,547 个 token）上打分。判定规则：两个均值之差大于双方种子间差距中的较大者才算有结论，两个种子方向相反时要补第 3 个种子。这是项目自己定的启发式规则，不是统计显著性检验；本报告里的“差异不显著”都是按这条规则说的。

- **最大的单项改进是 RoPE**，val loss 低 0.0523（约 3.3%），参数还少 1.4%。在 2 倍训练长度上打分时，RoPE 的后半段 loss 是 2.30 和 2.13，正弦是 4.93 和 5.06；但后半段同时变长了上下文，这个差值不能全算到“位置超范围”上。
- **Post-LN 在高学习率下学不动：** 学习率 3e-3 时停在 5.83–5.85，接近只按词频猜的水平；同样学习率的 Pre-LN 正常收敛。没有检查权重，所以“为什么学不动”是推断。
- **KV 缓存（对照结构开、关缓存）：** B=32 时生成快 6.80 倍、显存峰值从 662 MiB 降到 267 MiB；B=1 时在 GPU 上几乎不提速，在 CPU 上快 7.42 倍。
- **GQA、MQA 换来的是显存：** 完整缓存从 MHA 的 4.50 MiB 降到 GQA-2 的 1.50 MiB（MQA 手算是 0.75 MiB）；B=32、有缓存时，显存峰值从对照的 267 MiB 降到 GQA-2 的 167 MiB。代价是 val loss 分别高 0.0114（GQA-2）和 0.0123（MQA）。

## 4. 载入 Qwen3-0.6B（M4）

Qwen3-0.6B 有 596,049,920 个参数，结构上和我们的实现有三处不同：每个头的维度是 128（不等于 C/h = 64）、q 和 k 在拆头之后各做一次 RMSNorm、SwiGLU 的隐藏维度是 3072。这三处加成配置开关，默认值不变，M1–M3 的结果能逐字复现。

- **对齐（Mac CPU，fp32）：** 三个提示的 logits 最大误差 4.77e-05、4.24e-05、1.73e-04，贪心生成和 `transformers` 完全相同。
- **误差从哪来：** 在代码副本里把 `scores / d**0.5` 改成官方的 `scores * d**-0.5` 后，每一层的误差都是 0.0，说明结构和权重映射没有差别，剩下的只是浮点舍入。
- **bf16（M5 补充）：** 官方的 RMSNorm 内部会先转 fp32。加上同样的开关后，RTX 5060 上 bf16 的分数最大误差从 0.65625 变成 0.0。

## 5. LoRA SFT（M5）

LoRA 装在每层的 q、k、v、out 投影上，alpha 16，学习率 2e-4，微批 2 × 累积 8，1 个 epoch（7,273 题，454 步），只对答案算 loss，梯度累积按整步的答案 token 数加权。评测用测试集里固定的 500 题，贪心解码，500 题的标准误约 2.2 个百分点。完整的表见 [experiments/m5_gsm8k/SUMMARY.md](../experiments/m5_gsm8k/SUMMARY.md)。

## 6. 排查过的几个问题

这些问题都不会报错，但会让结果出错。前四个都改了代码，并加了能抓住它的测试；第五个靠改配置（微批 4 × 4 改成 2 × 8）解决；最后一个是读源码时发现的，我们没有踩到。

| 现象 | 原因 | 怎么发现的 |
| --- | --- | --- |
| 配置写 `qk_norm: "false"` 却开启了 QK-Norm | Python 的 `bool("false")` 是 `True` | 需求审查实测 |
| 基座不给例子时答对的题被判错 | 基座答完会用 `[Question]` 接着编题，“最后一个数”取到了编出来的数 | 用真实模型试跑 40 题：旧规则 5/40，新规则 22/40 |
| 贪心解码的结果不可复现 | `top_k=1` 走的是抽样，分数并列时会随机选，bf16 下分数很粗 | 规范审查；改成 argmax 后加了并列的测试 |
| bf16 下和官方实现差 0.656 | 官方 RMSNorm 内部转 fp32，我们没有 | 在副本里只改这一处，误差变成 0.0 |
| 训练能跑但最长一批要 43 秒 | 4 × 4 的最长一批要 11 GB，显卡 8 GB，超出部分推断被放到了系统内存 | 显存短测专门跑最长的一批；改成 2 × 8 后 7,331 MiB |
| PEFT 对照如果用 HF 的 `DataCollatorForLanguageModeling`，会学不会停下 | 它把等于 pad 编号的标签都设成 -100；pad 和 eos 是同一个编号，答案最后的 eos 也被遮掉 | 需求审查读源码；对照用我们自己的数据整理和 loss，没有踩到 |

## 7. 局限

- **规模小：** 预训练的模型只有约 1,400 万参数，每个消融变体 1 亿 token，结构消融的结论未必能迁移到大模型。
- **种子少：** 每组 2 个种子；GQA-2 和 MQA 之间按规则需要第 3 个种子才能比较，没有补。
- **评测噪声大：** 500 题的标准误约 2.2 个百分点，bf16 的数值变化本身就能让准确率差一两个百分点。
- **没做的实验：** F3（LoRA 装在哪些层）、F5（全参微调）、更多 epoch、完整的 1,319 题测试集。
- **评测一次只答一题：** 模型没有 attention mask，长度不同的题不能拼成一批，评测 500 题要约 30 分钟。
- **审查：** 代码由 Claude 的只读子 agent 审查；Codex 对 M3–M5 的交叉审查还没做，做完后记录在 [docs/reviews/](reviews/)。

## 8. 如果有更多时间和算力

- 用完整测试集和更多种子重测 F1、F2，把噪声降下来，再判断 SFT 有没有用。
- 试更多 epoch、更大的学习率，或者换一个基座没怎么见过的任务，看 LoRA 能不能学到新能力。
- 给模型加 attention mask，支持批量生成，评测会快很多。
- 在更大的模型和更多数据上重做 A1–A4，看结论是否成立。
