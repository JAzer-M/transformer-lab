## M1 多头注意力（2026-10-28）

### 1. 用自己的话讲一遍多头注意力是怎么做的
- **你的回答**：把 C 维拆成 h 个 d 维，做 h 次单头注意力，中间过程和单头一样；contiguous 是因为转置不搬动内存，view 之前要先把数据按新顺序排好。
- **评价**：三个要点都对。“多头分别负责不同的特征”这一句不够准确。
- **参考答案**：头是在 `q_proj` 之后、用 view 切出来的。每个头在自己**学到的** d 维子空间里，有一张独立的注意力表，因此可以关注不同的 token 关系；切分的并不是原始输入的特征。合头时先 transpose 再 view，中间必须 contiguous。
- **状态**：✅

### 2. 单头和多头（d_model 相同）的参数量一样吗？计算量呢？
- **你的回答**：参数量不一样，多头多出 h 和 d；计算量一样。
- **评价**：参数量答错了；计算量答对了。
- **参考答案**：**参数量完全一样**。两者都是 4 个 (C, C) 的投影矩阵，拆头只是把同一个向量换个形状来看，不增加参数。**计算量也基本一样**：投影部分相同；注意力分数部分，多头是 h × T² × d = T² × C，和单头的 T² × C 相等。

## M1 里程碑自测（2026-10-31）

### 19. 写出多头注意力每一步的形状（B = 2、T = 5、C = 8、h = 2）
- **你的回答**：x 是 (B, T, h, C/h)，q 和 x 一样；d = 4；transpose 交换 T 和 h；scores 最终是 T×T；第 8 步的转置不知道；contiguous + view 按 BTC 划分。
- **评价**：最关键的错误是以为输入一开始就有“头”。换一组数字（C = 6、h = 3）后答出 d = 2。

- **状态**：🟡（PROGRESS 建议择机复测）

### 20. 注意力里为什么要除以 √d？
- **你的回答**（讲解之后的复述）：d 大时概率分布会一边倒；用 Var(aX) = a²Var(X)，除以 √d 后方差变小，分布更平衡。追问：q·k 原本的方差怎么算？
- **参考答案**：q、k 的各分量独立、均值 0、方差 1 时，q·k 是 d 项之和，方差为 d、标准差为 √d。不缩放的话，d 越大 softmax 越接近 one-hot，进入饱和区，梯度接近 0，难以训练。除以 √d 后方差回到 1，与 d 无关；除以 d 则缩过头，注意力会接近均匀分布。
- **状态**：✅

### 21. 因果掩码怎么实现？为什么填 -inf 而不是 0？去掉掩码会怎样？
- **你的回答**：(T, T) 的矩阵，上三角填 -inf，用了 masked_fill，另一个函数忘了；因为 e^-inf = 0；去掉会过拟合。
- **评价**：前两问基本对；加分题错了。
- **参考答案**：用 `torch.triu(ones, diagonal=1)` 生成掩码，对角线不屏蔽，在 softmax **之前**用 `masked_fill` 加到 scores 上。填 0 的话 e^0 = 1，未来位置仍会分到权重。去掉掩码不是过拟合，而是**信息泄露**：目标就在输入里，模型直接抄答案。实验中 train 和 val loss 都降到约 0.05，但生成的全是乱码。
- **状态**：🟡

### 22. 残差连接和 LayerNorm 各起什么作用？Pre-LN 和 Post-LN 有什么区别，为什么现代模型用 Pre-LN？
- **你的回答**：残差保留之前的特征，防止在深层网络中被遗忘；LN 对最后一维做归一化，让数值在 0 附近；Pre-LN 和 Post-LN 的区别在于什么时候做残差；第二小问不知道。
- **评价**：残差只答了一半；LN 基本对；Pre/Post-LN 的区别答错了。
- **参考答案**：残差更关键的作用是梯度：∂(x + f(x))/∂x = 1 + ∂f/∂x，梯度有一条直通路，深层网络不容易梯度消失。LN 对**每个 token 自己的 C 维特征**做标准化（均值 0、方差 1），再乘可学习的 weight、加 bias；它和 BatchNorm 不同，不跨样本计算。Post-LN 是 `LN(x + f(x))`，LN 挡在主干道上；Pre-LN 是 `x + f(LN(x))`，主干道上只有加法。文献认为 Pre-LN 训练更稳定，对学习率和 warmup 不敏感；我们的小实验没有干净地复现这一点，留给 A2 消融验证。
- **状态**：🟡（PROGRESS 建议择机复测）

## M2 任务 C：梯度累积与梯度裁剪（2026-11-01）

### 25. 梯度累积时忘了把 loss 除以 K，会怎样？用 AdamW 和用 SGD 时影响一样吗？
- **你的回答**：除以 K 相当于求平均，不除的话某一次较大的 loss 会影响全局；SGD 受的影响更大。
- **评价**：“相当于求平均”和“SGD 影响更大”都对；原因说得不准确。
- **参考答案**：不除以 K，每一步的梯度都**稳定地变成 K 倍**，和个别 loss 大不大无关。SGD 的更新量 = lr × 梯度，相当于把学习率乘了 K（实测比值 4.000）。Adam 用 m/√v 归一化，梯度整体放大会被抵消（实测比值 1.000）。但开了梯度裁剪时，K 倍梯度会更频繁地触发裁剪；日志里的 loss 也会变成 K 倍。所以仍然要除以 K。
- **状态**：🟡

### 26. 梯度裁剪为什么整体按比例缩小，而不是逐个分量截断？
- **你的回答**：只改局部不改全局，相当于随意修改数据。
- **评价**：直觉对，表述可以更准确（改的是梯度，不是数据）。
- **参考答案**：逐个分量截断会改变各分量之间的比例，也就是**改变梯度的方向**（例子：(3, 0.5) 截断成 (1, 0.5)，方向从 9.5° 变成 26.6°）。按范数整体缩放只改长度，方向不变。PyTorch 中前者是 `clip_grad_value_`，后者是 `clip_grad_norm_`，训练大语言模型几乎都用后者。
- **状态**：✅

## M2 里程碑自测（2026-11-02）

### 27. 交叉熵 loss 和困惑度是什么关系？
- **你的回答**：交叉熵是 -ylogy-y；困惑度不知道。
- **评价**：交叉熵的公式写错了。
- **参考答案**：CE = −Σ yᵢ log ŷᵢ，其中 y 是 one-hot 的真实答案，ŷ 是 softmax 输出的概率，所以 CE = −log（模型给正确 token 的概率）。困惑度 PPL = e^CE，可以理解为模型平均在几个等可能的候选里犹豫。M2 第 0 步 PPL 约 8,707（接近词表大小 8192，等于乱猜），训练结束约 3.87。按字符和按 BPE token 算出的值单位不同，不能直接比较。
- **状态**：⬜

### 28. AdamW 和 Adam 的区别
- **你的回答**：都是针对学习率的优化器，区别忘了。
- **评价**：它们是更新参数的优化器，不是优化学习率的。
- **参考答案**：Adam 为每个参数维护动量 m（梯度的平均）和 v（梯度平方的平均），更新量 ≈ lr · m/√v。两者唯一的区别在权重衰减：Adam 把 λθ 加进梯度，于是衰减也被除以 √v，梯度大的参数几乎不衰减；AdamW 把衰减和梯度分开，直接作用在参数上：θ ← θ − lr·(m/√v + λθ)，叫“解耦的权重衰减”。我们用的是 `AdamW(weight_decay=0.01)`。
- **状态**：⬜

### 29. warmup 是什么？为什么需要？
- **你的回答**：不知道。
- **参考答案**：训练开头的一段时间里，学习率从很小线性升到设定值（M2 中：300 步内从 2e-6 升到 6e-4）。原因有二：一是刚初始化时梯度又大又乱，一开始就迈大步容易把模型推坏，loss 飙升甚至 NaN；二是 Adam 的 v 在开头只看了几个 batch，估计不准，m/√v 可能偏大。
- **状态**：⬜

### 30. bf16 和 fp16 的区别（顺带区分 int）
- **你的回答**：是精度上的区别；对 int、bf、fp 有些混淆。
- **参考答案**：浮点数是二进制的科学计数法，指数位决定范围，尾数位决定精度。fp32 = 8 位指数 + 23 位尾数；fp16 = 5 位指数 + 10 位尾数（最大 65,504，太小的梯度会变成 0，必须配合 GradScaler）；bf16 = 8 位指数 + 7 位尾数（范围和 fp32 一样，精度只有 2–3 位有效数字，不需要 loss scaling，所以我们在 5060 上用 bf16 autocast）。int 是整数，没有小数部分：int8 的范围是 −128 到 127，多用于推理时的量化；我们存 token 编号用的是 uint16（0 到 65,535），只用来存储，送进模型前转成 int64。
- **状态**：🟡

## M3 RMSNorm 与 Pre/Post-LN（2026-11-03 提问，11-04 回答）

### 31. 把输入整体乘以 3，RMSNorm 的输出会怎样？（先不考虑 eps）
- **你的回答**：会变成原来的 1/√3 倍。
- **评价**：不对。可能和注意力里的“除以 √d”记混了。
- **参考答案**：**输出完全不变。** 均方根也跟着变成 3 倍，分子分母的 3 约掉：3x / RMS(3x) = 3x / (3·RMS(x)) = x / RMS(x)。实测 `[1, 2, 2, 4]` 和 `[3, 6, 6, 12]` 都输出 `[0.4, 0.8, 0.8, 1.6]`。这正是归一化要的效果：不管进来的向量多大，出去的大小都稳定。

- **评价**：第一问对，第三问方向对。
- **参考答案**：merge 是 W' = W + (alpha/r)·B·A，W' 的形状和 W 一样，推理时只算一次 x·W'ᵀ，和原模型的计算量完全相同，旁路那两次小矩阵乘法就省掉了。fp32：ΔW 比 W 小得多（实测典型大小 8.1e-4 对 1.6e-2），bf16 只有约 3 位有效数字，加进去会舍掉一部分。实测同样的 W 和 ΔW，在 bf16 下合并，ΔW 的误差占 2.8%；fp32 下几乎是 0。所以 `merge_lora` 发现 W 不是 fp32 时直接报错。
- **为什么用 bf16 不用 fp16**：两者都是 16 位，分法不同。fp16 的指数位少，最大只能表示 65,504（实测 70000 变成 inf），太小的梯度也会变成 0，训练时要配合 loss scaling 才不出错；精度高一些（最小间隔 0.00098）。bf16 的指数位和 fp32 一样多，范围相同（最大约 3.4e38，70000 变成 70144），不会溢出，也不需要 loss scaling；代价是精度低（最小间隔 0.0078，1 + 1/512 会变成 1）。训练时数值范围比精度更要紧，显卡也支持，所以用 bf16。
- **状态**：🟡

### 55. ★ LoRA 省下的是哪一部分显存？训练还要约 7.3 GB，花在哪里？

### 56. ★ LoRA、全参微调、QLoRA 的区别
- **你的回答**：LoRA 用低秩矩阵，只针对部分参数调参；QLoRA 也一样，但是量化过；全参微调调整所有参数，改动很大。
- **评价**：大体对。“只针对部分参数”要说准：LoRA 不是挑出一部分原有参数来训练，而是原有参数全部冻结、另外加一组新参数，并且对 W 的改动被限制成低秩的。
- **参考答案**：全参微调更新所有参数，每个参数都要存梯度和 Adam 状态，显存最大（上一题算的 8.88 GiB），在 8 GB 卡上放不下 0.6B 模型。LoRA 冻结原参数，只训练 B·A 这个低秩改动，我们的 r=4 到 32 只占 0.19%–1.54% 的参数。QLoRA 在 LoRA 的基础上，把冻结的基座量化成 4 位来存，基座权重从 fp32 的约 2.4 GB 降到约 0.3 GB，A、B 仍用高精度训练。

### 57. ★ SFT 为什么要去掉提示部分的 loss？为什么是 len(prompt_ids) − 1？

### 59. 为什么右边 padding 不需要 attention mask？换成左边会怎样？
- **你的回答**：不会。
- **参考答案**：因果掩码让每个位置只看自己和前面。pad 补在右边，在真实 token 的后面，真实 token 本来就看不到它们；pad 位置的目标又是 -100，不算 loss。RoPE 的位置也都从 0 数起，所以带不带 pad，真实 token 的分数都一样（测试证明了，审查在真实 Base、fp32 下实测差是 0）。如果补在左边，pad 在真实 token 前面，真实 token 会看到它们，结果就被污染了；真实 token 的位置也不再从 0 开始，RoPE 的角度全变了。这时就得加 attention mask 和位置编号。这也是我们评测一次只答一题的原因：批量生成通常要左边补齐。

### 60. 梯度累积为什么按整个 batch 的答案 token 数平均？

- **参考答案**：举例：微批次 1 有 10 个答案 token，loss 之和 10；微批次 2 有 100 个，loss 之和 50。各自平均再平均是 (1.0 + 0.5)/2 = 0.75，按 token 加权是 60/110 ≈ 0.545。各自平均时，短答案里的每个 token 权重大了 10 倍。按 token 加权就和一次算完整个 batch 完全相同（`test_accumulated_loss_is_weighted_by_answer_tokens`），也和把 batch 分成几份无关：2 × 8 和 4 × 4 第 1 步的 loss（0.92283）和梯度范数（2.4088）都相同。HF Trainer 以前就有过这个问题。
